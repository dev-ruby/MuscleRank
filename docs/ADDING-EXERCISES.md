# 운동 추가 / 랭크 설정 가이드

화면 디자인과 운동 데이터를 분리했습니다. 현재 3대 운동과 부위별 대표 운동 8개, 총 11개 운동이 서비스에 표시됩니다.

## 수정할 파일

| 파일 | 역할 |
| --- | --- |
| `dist/data/catalog.json` | 운동 목록, 언어별 이름, 입력 범위, 기준 무게, 근육별 가중치, 티어 경계 |
| `dist/data/locales.json` | 한국어/영어 화면 문구 |
| `dist/rank-engine.mjs` | 계산 및 데이터 검증. 일반적인 운동 추가 시 수정하지 않음 |
| `dist/app.js` | 목록·캐러셀·카드·그림을 데이터에서 생성 |
| `examples/overhead-press.json` | 체중 배수 모델의 구조 예시. 같은 ID의 운동이 이미 있으므로 그대로 추가하지 말고 새 고유 ID로 변경 |
| `dist/artwork/` | 추가 운동의 개별 투명 배경 PNG 그림 |

## 새 운동 추가

1. 예시 객체를 `catalog.json`의 `exercises` 배열 끝에 추가합니다.
2. `id`는 영문 소문자·숫자·하이픈으로 된 고유값을 씁니다. 저장 후 이름을 바꾸더라도 `id`는 유지하세요. 운동 순서는 자유롭게 바꿀 수 있습니다.
3. `name`, `title`, `equipment`에 `ko`, `en`을 모두 채웁니다. `title` 배열의 각 항목은 한 줄입니다.
4. `input.weight`에 최소/최대/단위를 지정합니다. `spacing`은 눈금 한 칸의 픽셀 수입니다. 값이 클수록 감도가 느립니다. 반복 수는 추정 공식 범위인 1~12회입니다.
5. `standard`에 해당 운동의 기준 무게를 넣습니다. 아래 두 방식 중 하나를 선택합니다.
6. `muscles`에 부위 ID와 가중치(0 초과~1)를 넣습니다. 예: `{"front-delts": 1, "side-delts": 0.65, "triceps": 0.5}`.
7. `artwork`는 단일 이미지일 때 `{"src":"./my-exercise.png","columns":1,"index":0}`입니다. 파일은 `dist`에 둡니다. 이미지가 없으면 `null`로 두어 기본 아이콘을 씁니다. 현재 이미지 3분할 스프라이트는 `columns:3`, `index:0~2`입니다.
8. `node scripts/validate-catalog.mjs`와 `node --test tests/rank-engine.test.mjs`를 실행합니다.

이후 페이지를 새로고침하면 운동 선택, 캐러셀, 입력 범위, 근육 카드, 랭크 계산에 자동으로 나타납니다. 새 운동에는 임의 기록이 생기지 않으며, 처음 방문한 사용자의 모든 운동 값은 빈 상태로 시작합니다.

`totalExerciseIds`는 3대 합계에 포함할 ID입니다. 일반적인 신규 운동은 여기에 추가하지 않습니다. 종합 랭크에는 유효하게 기록한 모든 운동이 들어가지만, 3대 합계는 스쿼트·벤치·데드만 합산합니다.

## 기준 무게의 두 가지 방식

### 1. 체중·키 보정 (`allometric`, 기존 운동)

```text
기준 = reference1RMKg[성별]
     × (체중 / referenceBodyweightKg) ^ bodyweightExponent
     × (referenceHeightCm / 키) ^ heightExponent
점수 = 추정 1RM / 기준
```

현재 기준 체중 70kg·키 170cm에서 점수 1.0에 해당하는 무게:

| 운동 | 남성 | 여성 |
| --- | ---: | ---: |
| 스쿼트 | 105kg | 71.4kg |
| 벤치프레스 | 75kg | 41.25kg |
| 데드리프트 | 130kg | 91kg |
| 랫풀다운 | 65kg | 40kg |
| 바벨 컬 | 35kg | 20kg |
| 시티드 레그 컬 | 50kg | 32.5kg |
| 오버헤드 프레스 | 45kg | 27.5kg |
| 케이블 푸시다운 | 30kg | 17.5kg |
| 레그 익스텐션 | 65kg | 40kg |
| 스탠딩 카프 레이즈 | 80kg | 50kg |
| 케이블 크런치 | 40kg | 25kg |

추가된 8개 운동은 체중 지수 `.67`, 키 지수 `0`을 사용합니다. 위 무게와 가중치는 MVP의 조정 가능한 제품 설정이며, 실제 인구의 백분위나 공인 기준표에서 가져온 값이 아닙니다. 기존 3대 운동의 계산은 유지했습니다.

### 추가 운동의 기록 방식과 부위 연결

| 운동 | 기록할 중량 | 부위 가중치 |
| --- | --- | --- |
| 스쿼트 | 바와 양쪽 원판을 합한 총중량 | 대퇴사두·내전근 1, 둔근 0.6 |
| 벤치프레스 | 바와 양쪽 원판을 합한 총중량 | 가슴 1, 전면 삼각근 0.45, 삼두 0.65 |
| 데드리프트 | 바와 양쪽 원판을 합한 총중량 | 척추기립근 0.8, 승모근 0.35, 둔근 0.8, 햄스트링 1 |
| 랫풀다운 | 머신에 표시된 선택 중량 | 광배근 1, 견갑 주변근 0.35, 이두 0.4 |
| 바벨 컬 | 바와 양쪽 원판을 합한 총중량 | 이두 1, 전완 0.35 |
| 시티드 레그 컬 | 머신에 표시된 선택 중량 | 햄스트링 1 |
| 오버헤드 프레스 | 바와 양쪽 원판을 합한 총중량 | 전면 삼각근 1, 측면 삼각근 0.65, 삼두 0.5 |
| 케이블 푸시다운 | 머신에 표시된 선택 중량 | 삼두 1 |
| 레그 익스텐션 | 머신에 표시된 선택 중량, 양발 수행 | 대퇴사두 1 |
| 스탠딩 카프 레이즈 | 머신 표시 중량 또는 추가 원판 총중량, 체중 제외 | 종아리 1 |
| 케이블 크런치 | 머신에 표시된 선택 중량 | 복직근 1 |

머신·케이블은 도르래 비율과 기구 구조에 따라 같은 표시 중량의 저항이 다릅니다. 같은 기구에서 기록을 비교하는 용도이며 머신 간 동등한 저항을 보장하지 않습니다. `quads`는 현재 대퇴사두·내전근을 묶는 ID입니다.

현재 체중 지수 `.67`, 키 지수 `.15`는 기존 MVP와 점수를 유지하기 위한 **임시 설정**입니다. 검증된 표준으로 주장하지 않습니다. 키 보정을 제외하려면 해당 운동의 `heightExponent`를 `0`으로 설정하세요.

### 2. 체중 배수 (`bodyweight-ratio`)

```json
"standard": {
  "model": "bodyweight-ratio",
  "referenceRatio": { "male": 0.65, "female": 0.4 }
}
```

기준 무게 = 체중 × 성별 기준 배수. 키는 기록하지만 이 방식에서는 계산에 반영하지 않습니다. 위 숫자는 오버헤드 프레스 추가 방법을 보여주는 **예시**이며 실제 기준으로 검증되지 않았습니다.

점수 1.0 기준을 지정하면 공통 `tiers[].minScore`를 사용합니다. 예를 들어 골드 시작값 `.85`일 때, 기준 배수가 `1.5`라면 골드 시작은 체중의 `1.275`배입니다. 티어별 경계값은 JSON에서 조정할 수 있고, 배지 디자인 순서는 기존 9단계를 사용합니다.

## 근육별 가중치

```text
부위 점수 = Σ(유효한 운동 점수 × 해당 부위 가중치) / Σ(해당 가중치)
```

- 현재 둔근에는 스쿼트 `0.6`, 데드리프트 `0.8`이 연결되어 있습니다.
- 두 운동이 모두 기록되면 반영 비중은 각각 약 43%, 57%입니다.
- 하나만 기록되면 그 운동 점수를 사용합니다. 기록하지 않은 운동은 0점으로 취급하지 않습니다.
- 가중치는 점수의 상대적 반영 비중이며 근활성도·근성장 효과의 측정치가 아닙니다. 작은 가중치 자체가 낮은 티어를 의미하지도 않습니다.
- 동일 운동은 ID별 한 기록만 저장하므로 같은 기록을 반복 입력해도 누적 보너스가 없습니다.
- 해당 부위에 기록이 하나도 없으면 회색/미평가로 표시합니다.

### 세부 부위 ID

| 영역 | 부위 ID → 표시 이름 |
| --- | --- |
| 가슴 | `chest` → 가슴 |
| 어깨 | `front-delts` → 전면 삼각근, `side-delts` → 측면 삼각근, `rear-delts` → 후면 삼각근 |
| 등 | `lats` → 광배근, `traps` → 승모근, `scapular` → 견갑 주변근, `erectors` → 척추기립근 |
| 팔 | `biceps` → 이두, `triceps` → 삼두, `forearms` → 전완 |
| 코어 | `abs` → 복직근, `obliques` → 복사근·옆구리 |
| 하체 | `quads` → 대퇴사두·내전근, `glutes` → 둔근, `hamstrings` → 햄스트링, `calves` → 종아리 |

기존 `shoulders`, `back`, `core`는 위의 세부 ID로 대체했습니다. 새 운동에는 해당 세부 ID를 사용하세요. 기존 운동 ID와 저장 키는 유지하므로 사용자가 저장한 무게·반복 수는 보존되고 부위 점수만 재계산됩니다.

후면 삼각근과 복사근은 현재 11개 운동에 연결하지 않았습니다. 연결 운동이 없어도 부위 카드와 그림은 **미평가**로 남습니다. 운동을 추가하면서 `rear-delts` 또는 `obliques`에 가중치를 지정하면 자동으로 계산됩니다. 기존 운동이 주변 부위를 보조한다는 이유만으로 모든 세부 부위를 평가하지 않습니다.

바디그래프는 표면 구역을 단순화한 그림입니다. `scapular`는 견갑 주변의 작은 근육 구역을 함께 표시하며, 깊은 근육인 능형근만을 구분해 그린 영역은 아닙니다. 세부 근육의 독립적인 힘을 직접 측정한 결과로 해석하지 않습니다.

`muscles[].parts`는 몸 그림의 SVG 구역 이름입니다. 기존 부위에 운동을 연결하면 그림 코드 수정은 필요 없습니다. 완전히 새로운 근육 구역을 그리려면 그림 데이터도 확장해야 합니다.

`dist/body-model.js`의 `front`/`back`에 `slug`와 SVG `paths`를 정의합니다. 어깨 세부 구역에는 원래 윤곽을 유지하기 위한 `clipPaths`도 있습니다. 동일한 부위를 앞·뒤 모두 그릴 때는 같은 `slug`를 사용하고, 한 면 안에서는 중복하지 않습니다. 새 부위를 추가할 때 `dist/app.js`의 `bodySections`에도 ID를 연결하면 몸 부위별 정렬에서 해당 영역에 배치됩니다.

## 설계 근거와 한계

체중 배수만으로 비교하는 단순 방식과 체중을 비선형 보정하는 방식을 모두 지원합니다. IPF의 [GL 계수 설명(2020 자료)](https://www.powerlifting.sport/fileadmin/ipf/data/ipf-formula/IPF_GL_Coefficients-2020.pdf)은 체중 증가와 상대적인 힘의 관계, 성별·종목별 계수 구분을 설명합니다. 다만 대회용 종합/벤치 공식이므로 이 앱의 모든 신규 운동이나 근육 점수에 그대로 적용하지 않았습니다.

현재 Wood~Olympian 경계, 성별 기준, 키 보정, 근육 가중치는 제품용 초기 설정이며 공식 순위·백분위가 아닙니다. 실제 기준표를 확보하면 `standard`, `tiers`, `muscles` 데이터를 교체하고 `calibrationVersion`을 올리세요. 기록 원본은 그대로 두고 점수를 다시 계산합니다.

## 저장과 번역

- 언어 선택: `musclerank-language`, 새로고침 후 유지.
- 기록: `musclerank-records-v3`, `profile`과 운동 ID별 `records` 저장.
- 기존 `musclerank-reference-ui-v2` 기록을 자동으로 가져옵니다. 기존 저장 키는 삭제하지 않습니다.
- 운동을 추가해도 기존 기록을 덮어쓰지 않습니다. 잠시 목록에서 뺀 운동의 저장값도 유지됩니다.
- 백엔드나 계정 간 동기화 없이 이 브라우저에 저장되는 기존 방식입니다.
- 번역 문구의 `{count}` 같은 변수명은 양 언어에서 같아야 합니다. 검증 스크립트가 누락과 불일치를 확인합니다.

## 지원 범위

현재 입력은 외부 중량 kg와 반복 수를 이용한 1RM 운동입니다. 맨몸/보조 머신의 유효 중량, 시간·거리 운동은 아직 지원하지 않습니다. 이런 운동은 단순 JSON 추가에 앞서 별도 점수 모델과 입력 UI를 구현해야 합니다.
